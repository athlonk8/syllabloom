# 用户指南

[English](USER_GUIDE.md) · 中文

Syllabloom 的目标是让几个月后的学习记录仍然可理解：来源链接会保留，原始资料和个人工作区分开，你的答案始终是自己控制的普通 Markdown 文件。

## 推荐学习循环

1. 导入一门公开课程。
2. 在 Syllabloom 中观看可嵌入的讲次。
3. 准备书写时导出笔记到 Obsidian。
4. 对公开官方作业，下载来源并创建工作区。
5. 自己编写或修订 Answer.md。
6. 只有需要反馈时才提交，确认数据边界并查看保存的反馈。
7. 持续重复。较早的提交快照可以保留并用于比较。

## 导入 YouTube 课程

打开 Add course，选择 YouTube API 并输入公开视频或播放列表网址。要自动获取元数据，请先在 Settings 填写 YouTube Data API key。导入器只读取官方 API 提供的标题、频道、有序视频、时长、缩略图、描述和发布时间，不抓取 YouTube 网页。

没有 key 时，选择 Manual fallback，输入课程名和公开视频网址即可开始。手动模式故意保持有限：它不会通过网页抓取来伪造一个播放列表。

播放器使用 YouTube IFrame Player API，播放时会周期性记录短观看区间。大幅向前跳转会被当作 seek，不计入已覆盖内容。重叠或重复区间会合并，因此反复观看不会虚增进度。下次打开讲次时会使用最近保存的位置继续。

若发布者关闭嵌入或视频被移除，应用会显示嵌入不可用，但仍保留官方来源链接，不会自动跳转。

## 使用 B 站来源与自己的账号

> **登录回跳：** 点击“登录后返回播放器”会在当前标签页打开 B 站官方登录页。登录成功后会自动回到同一课程和讲次，清除一次性回跳参数，并重新加载页面内播放器；无需再手动切换标签页。Syllabloom 不会读取密码、二维码或 Cookie。“重新加载页面内播放器”仅作为手动回退。

在某一讲下展开“使用 B 站来源”，粘贴直接包含 `BV...` 的视频链接。它会被清楚标记为学习者选择的第三方来源，不会被伪装成官方课程材料。

嵌入播放器会请求 B 站的高质量模式，但最终可选清晰度仍由 B 站、视频本身、账号权限、网络状况和浏览器隐私设置决定。点击“登录后返回播放器”会在当前标签页打开 B 站自己的登录页面；Syllabloom 不会收到密码、二维码或 Cookie。登录成功后会回到同一课程并自动重载 iframe。“重新加载页面内播放器”只会重新加载官方 iframe；应用刻意不再提供跳到 B 站完整站外播放器的按钮。iframe 不包含弹窗或外层导航权限，因此其中的操作不能把 Syllabloom 外层页面带离课程工作区；但在学习者点击播放器后，它可向浏览器申请读取 B 站登录会话的存储权限。如果重新加载后选择 720P 仍没有反应，说明浏览器仍拦截了 B 站的第三方会话存储，或 B 站没有向该嵌入播放器提供此清晰度。若 B 站播放器本身针对嵌入播放显示“进入哔哩哔哩，观看更高清”的提示，该提示仍会显示，但不能带走外层课程页面。“全屏”会在浏览器允许时于页面内放大播放器。

## 导入 Stanford 课程

选择 Stanford URL，粘贴公开 Stanford 课程页。导入器会：

1. 检查站点 robots 政策。
2. 读取输入页面及一个数量有限的同域课程、日程、讲次、资料和作业链接。
3. 记录发现的 slides、PDF、notebook、GitHub、阅读资料、作业和受保护资源，以及发现它们的页面。
4. 在 Canvas、SSO、Gradescope 和其他认证边界停止。

看起来需要登录的页面会保留为 protected 来源。你会在来源溯源区域看到它需要 Stanford 身份验证，但应用不会穿过登录页，也不会把它从记录中静默丢掉。

SYLLABLOOM_CRAWL_MAX_PAGES 和 SYLLABLOOM_CRAWL_MAX_DEPTH 可以控制导入边界。较小的值让导入更可预测，并尊重来源网站。

## 理解来源与作业

Syllabloom 不猜测某个资源是否官方。只有公开官方课程页直接链接到的资源才会被视为官方作业。课程页、资源地址、访问状态、本地路径、下载后的校验和以及其他溯源字段都会保留。

课程页面会区分：

- 官方来源资料：来自公开来源的链接或下载原件。
- 个人工作区：你编写和测试答案的本地位置。
- 提交快照：请求反馈那一刻生成的不可变副本。

因此，提交后再编辑 Answer.md 不会修改早期快照或其反馈。

## 安全使用 Obsidian

在 Settings 中设置一个已存在的 Vault，然后使用 Export Obsidian notes 或作业中的 Create notes。Syllabloom 只会创建自己的 AI-Learning 子目录。典型作业目录如下：

    AI-Learning/
      course-name/
        Assignments/
          assignment-key/
            Assignment.md
            Answer.md
            Feedback.md

Answer.md 是 Syllabloom 与 Obsidian 共用的答案文件。可以在任一端编辑；如果已有 Answer.md，应用会保留它而不会覆盖。

Docker 安装时必须先将 Vault 挂载到容器。参见 [安装指南](INSTALLATION.zh-CN.md#docker-中使用-obsidian)。

## 下载并准备官方作业

对未受保护的官方作业：

1. 选择 Download original。应用将文件保存在本地 LearningVault，并与个人工作区分开。
2. 选择 Create notes。若已配置 Vault，会创建 Obsidian 文件并准备本地工作区。
3. 如需由操作系统打开已验证的本地目录，选择 Open workspace。

受保护作业不会提供下载，这是有意设计。课程溯源会保留，让你知道为何没有下载按钮。

## 网页内作答、保存与获取反馈

点击作业卡片的“打开作业工作区”。左侧保留公开作业说明和关联资料，右侧提供 Markdown 答题编辑器。配置 Obsidian 后，它会编辑同一份 `Answer.md`；未配置时，答案保存在 Syllabloom 本地 `LearningVault`。

可随时点击“保存草稿”。之后使用“保存提交版本”创建不可变的本地快照；此步骤不会把内容发送给 Codex、OpenAI、Stanford 或课程平台。选择一个已保存版本、勾选明确确认框后，点击“使用已配置的 Codex 评分”。反馈面板会显示 AI 估算分数、置信度、能力分项、详细解释、可能的逐题/逐要求反馈、优点、待改进点和建议复习主题。

## 获取反馈

提交前先在 Settings 选择提供方。

| 提供方 | 工作方式 |
| --- | --- |
| Codex CLI | 原生启动时应用暂存一个作业副本，并在只读 sandbox 中运行 Codex。 |
| 兼容 OpenAI 的端点 | 仅发送暂存 Answer.md、有限公开作业上下文、政策文本和可用的官方测试摘要。 |
| Disabled | 不请求 AI 反馈。 |

每一次提交都必须勾选确认框，它不是一次性的全局同意，而是确认你要把当前暂存快照发送给已配置的提供方。

有公开测试时，应用会先运行测试，再请求可选 AI 反馈。反馈定位于循序渐进的复习建议，而不是完整解答。远程提供方可能收费并有自己的隐私政策。

使用 Show grading history 查看快照和评分。修订 Answer.md 后再次提交会创建新版本，旧版本会保留。

## 证书

课程达到完成政策后，Syllabloom 可以生成本地独立学习证书。完成通常要求达到设置的不重复视频观看阈值，并通过必需的公开官方作业。配置了 mastery 规则时，也可能要求各作业分数和平均分。

该证书不是大学签发、认证、赞助或背书的凭证；它不使用大学徽标，也不宣称官方课程学分。

## 语言与可访问性

首次打开默认英语。随时使用侧栏底部 English 或 中文。课程标题、来源描述和外部网站内容会按原样保存；切换界面语言不会翻译第三方课程内容。

界面首次打开时会跟随系统的深浅色偏好。使用侧栏底部的主题控件可选择浅色或深色，浏览器会记住明确选择。

语言控件是带 lang 查询参数的真实链接，因此保存或分享的网址也可以直接指定语言。

## 保持健康的本地记录

- 定期备份原生数据目录或 Docker volume。
- 独立备份 Obsidian Vault；它是你的长期知识库。
- 不要把 API key 放入截图、issue、提交记录或共享的 .env 文件。
- 在把导入资料当成课程要求前，先核验来源。
- 需要比较学习过程时查看历史，而不是覆盖旧作业。

安装和恢复请见 [安装指南](INSTALLATION.zh-CN.md)，信任边界和溯源模型请见 [架构说明](ARCHITECTURE.md)。
